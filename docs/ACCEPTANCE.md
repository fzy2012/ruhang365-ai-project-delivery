# Phase 1 验收基线

| ID | 验收项 | 通过标准 | 验证方式 |
|---|---|---|---|
| P1-01 | 独立目录 | 使用用户指定目录，未修改 RHZL 或其他项目 | 路径与 Git 状态检查 |
| P1-02 | Git 基线 | 本地仓库使用 `main` 分支，无远程仓库 | `git status`、`git remote -v` |
| P1-03 | 项目规则 | `AGENTS.md` 明确产品、阶段、安全和验证边界 | 静态合同检查 |
| P1-04 | 产品规格 | 覆盖用户、非目标、复杂度、买配连改建、闸门与交付对象 | 文档审查 |
| P1-05 | Skill schema | `SKILL.md` frontmatter 和命名通过官方验证 | `quick_validate.py` |
| P1-06 | 触发边界 | 新项目/零代码/端到端触发，小修改默认不触发完整流程 | 描述与评测审查 |
| P1-07 | 渐进加载 | Skill 核心精简，详细模板位于一层 references | 目录与引用检查 |
| P1-08 | 决策协议 | 推荐优先、业务后果、替代项、回复方式完整 | 决策模板检查 |
| P1-09 | 双层验收 | 用户验收与工程验收分离，状态定义完整 | 验收模板检查 |
| P1-10 | 交付闭环 | 访问、使用、维护、恢复和交接均有字段 | 交付卡检查 |
| P1-11 | 三类评测 | 简单任务、新项目、现有高风险项目案例冻结 | JSON 与 rubric 检查 |
| P1-12 | 静态验证 | 官方 Skill 验证、项目合同、JSON 和 diff 检查通过 | 命令回执 |
| P1-13 | Codex 项目 | 用户指定目录出现在 Codex 项目列表且路径准确 | Codex 项目列表 |
| P1-14 | 权限边界 | 未安装、未创建远程、未改 RHZL、未部署 | 文件系统、Git 和项目状态检查 |

## 本阶段不作为 PASS 的项目

- 独立模型前向评测；
- 全局 Skill 安装与隐式触发；
- 公开 GitHub Core；
- RHZL 页面与 Preview；
- 合并和 Production；
- 真实用户价值与商业结果。

这些项目必须在后续阶段分别建立证据，不能由 Phase 1 静态验证推断。
